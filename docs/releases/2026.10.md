# vpnbot 2026.10

The first release with the button interface. Everything since `2.0` (Aug 2025, `release/2.0`).

## For users

- **Menu instead of commands.** `/menu` opens the home card: your nodes, one button per region, Stop
  buttons, Refresh and Help. Tap a city to start a node; the message turns into the node card with
  the hostname, the public IP and the exit-node guide, and later into the stopped card.
- **Nodes report themselves.** The node agent edits the card as the node comes up, warns silently
  before the idle stop and marks the stop in the same message. Start is about 20 s faster.
- **Access requests.** A newcomer taps *Request access*; the admins get a message with role
  checkboxes (node admin, read-only, user admin), the requester is told the outcome.
- **Users screen** for admins: roles per user with toggles, removal with confirmation.
- **Region requests.** *Other region…* lists the AWS regions enabled for the account that are not
  set up yet; a request goes to the owner with *Deployed, notify* and *Decline*, and the requester is
  told when the region is available.
- English and Russian.

## Under the hood

- Identity by Telegram user id (a renamed account keeps its access, a freed username cannot be
  taken over); users pre-registered by username before this release are migrated on first contact.
- Runtime configuration in one DynamoDB table (regions, users, requests, update locks); the Lambda
  left its VPC, NAT instance and EFS, and starts with SnapStart: cold start 5.4 s → 2.5–3 s, warm
  requests 0.1–0.3 s; about $13/month less.
- The text commands that duplicate buttons are gone; `/help`, `/version`, `/supportedRegions`,
  `/describeRoles` remain as system commands.
- One composition root (`BotDependencies`), sealed `UiAction` records for the buttons, calendar
  versioning, a `Release` workflow that deploys code, stack and every region from a `release/*` push.
- `README.md` with the setup from scratch.

## Upgrading from 2.0

Follow `docs/specs/infra-cleanup-phase3.md` §11 and `docs/specs/access-admin-phase4.md` §11 in
order (DynamoDB table, Lambda stack without VPC, user migration script), then push `release/2026.10`.
